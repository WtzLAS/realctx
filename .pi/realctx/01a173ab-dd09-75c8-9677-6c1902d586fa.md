Defaults: `src/config.ts`; trigger logic: `extensions/realctx/context-layer.ts` (transform ~L603-655; `estimateUsage` ~L670).
- Safe input window = `contextWindow - min(model.maxTokens, 25% of contextWindow)`; thresholds are shares of this window.
- History defaults: `prepareThreshold` 0.3, `protectTurns` 24, `minChunkTokens` 8000, `maxChunkTokens` 50000, `prepareMaxTokens` 0. Preparation runs in the background without applying summaries; keep prepareThreshold below applyThreshold.
- Context defaults: `applyThreshold` 0.4, `captureMinTokens` 0, `dropMinTokens` 0, `protectTurns` 24, `imageMaxTurns` 8, `applyMaxTokens` 0, `emergencyThreshold` 0.8. Apply combines queued drops and prepared history chunks; emergency applies everything and drops largest old outputs, with deterministic history fallback if no chunk is ready.
- Also applies regardless of usage on cold prompt cache or `/realctx flush`. In v3, `context.cacheTtl` no longer exists: there is no universal 5m lifetime since the last assistant response. Cold-cache applies only when the active model's resolved lifetime is known and has elapsed. Resolution uses per-model `cacheTtlByModel` overrides, then automatic metadata/provider estimates when `cacheTtlAuto=true`. Native Anthropic/OpenAI models with caching evidence may use a labeled 5m estimate; unknown providers/gateways do not. Unknown lifetime means threshold/emergency/flush-only.
- Normalization clamps applyThreshold ≤ emergencyThreshold. Protected turns, `protectedTools`, and outputs below `dropMinTokens` are never dropped; general protected-turn rules take priority over image age.
- `SETTINGS_VERSION` is 3; `Settings` has a `version` field. Missing version means v1. Loading pre-v3 files intentionally resets ALL saved Context and History values, including custom values. Other sections—including connections/API keys, rewriteModel, memory settings, and memories—are preserved.
- `loadSettings` writes a unique 0600 backup next to `config.json` before atomic rewrite. Failures keep the old file and apply defaults only in memory with a warning. `MemoryEngine` queues migration warnings for the Pi extension to notify once. Current-version configs and `normalizeSettings(partial)` do not migrate.
- When changing defaults existing users should receive, bump `SETTINGS_VERSION`, update `migrateSettings`, add tests in `tests/policy.test.ts`, and update `README.md` (Context layer + History sections) and the `docs/realctx-design-v2.md` settings table together.
- Regression checks: `npm run typecheck && npm test`; there is no `npm run check` script.
