Defaults in `src/config.ts`; trigger logic in `extensions/realctx/context-layer.ts` (transform, ~L603-655; `estimateUsage` ~L670).
- Safe input window = `contextWindow - min(model.maxTokens, 25% of contextWindow)`; all thresholds are shares of this.
- `history.prepareThreshold` 0.25: historian prepares summaries in background (not applied yet). Keep it below applyThreshold so a part is ready when drops apply.
- `context.applyThreshold` 0.35: queued drops + prepared history chunks are applied in one pass.
- `context.emergencyThreshold` 0.9: apply everything + drop largest old outputs; deterministic history fallback if no chunk ready.
- Also applies regardless of usage when prompt cache is cold (`context.cacheTtl` 5m since last assistant response, `cacheTtlByModel` overrides) or on `/realctx flush`.
- Normalization clamps applyThreshold ≤ emergencyThreshold. Never-dropped: last `protectTurns` (4) turns, `protectedTools`, outputs < `dropMinTokens` (1000).
- `SETTINGS_VERSION` is currently 2; `Settings` has a `version` field. Files without `version` count as v1. `loadSettings` runs `migrateSettings(s, from)` for older files and rewrites them via `saveSettings` (errors ignored). Saved configs contain every key, so migrations only move values still equal to the old default.
- v2 migrates `context.applyThreshold` 0.25→0.35 and `history.prepareThreshold` 0.2→0.25 (prepare only if apply > 0.25).
- When changing a default that existing users should get: bump `SETTINGS_VERSION`, add a step in `migrateSettings`, add a test in `tests/policy.test.ts`, and update `README.md` (Context layer + History sections) and `docs/realctx-design-v2.md` settings table together.
