- In Pi (`agent-session.js` `_afterToolCall`), extension `tool_result` handlers run before `normalizeToolResultImages` resizes images, potentially replacing image data or mime type and adding a `[Image resized …]` text hint. Thus `layer.capture` in realctx's `tool_result` handler gets the raw image. The `message_end` handler in `extensions/realctx/index.ts` detects changes via `sameContent` (comparing image `data` and `mimeType`) and calls `layer.recapture`, so the stored original matches what the model saw.
- Image tokens are no longer a flat 1200: `src/images.ts` calculates them from pixel size read from the encoded header and the session model's cost profile, `imageCostFor(ctx.model)`.
- User-pasted images are stored as one output per user message: tool `USER_IMAGE_TOOL` = "user" (`src/outputs.ts`), id `userImageId(m)` = `user-image:<messageKey minus "user:">` (`src/history.ts`), captured in `ContextLayer.captureUserImages` on every `context` request (no size minimum). When dropped, only the image parts of the user message become placeholder text; text parts stay.
- Because a rendered user message hashes differently in `messageKey`, `transform` computes `keys = messages.map(messageKey)` BEFORE rendering drops and passes them to `history.transform(..., { keys })` → `renderHistory(messages, chunks, keys)`. Any new code matching chunks against rendered messages must do the same.
- In `src/policy.ts`, `dropMinFor` lets image outputs drop from `IMAGE_DROP_MIN` = 200 tokens. Rule reason `"image"` drops images older than `context.imageMaxTurns` (default 6, 0 = off), after protected-tool/latest-snapshot checks. Judge image outputs get `candidate.images` plus an `[N images]` marker in the excerpt; a summarize verdict becomes drop, with no fact capture.
- Tests: `tests/images.test.ts` (unit), image e2e tests at the end of `tests/context.test.ts`; image header fixtures in `tests/fixtures-images.ts` (not a test file, but typechecked).
