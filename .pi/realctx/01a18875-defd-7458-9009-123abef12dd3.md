A tool call can have no `toolResult` anywhere in the transcript (Pi restarted/aborted while it ran, e.g. long `task_output wait_ms`). pi-ai `transformMessages` (node_modules/@earendil-works/pi-ai/dist/api/transform-messages.js) inserts a synthetic `"No result provided"` result before the next assistant/user message (system messages are held, transparent) and skips assistant messages with stopReason `error`/`aborted` entirely. `boundaries()` in `src/history.ts` (PR #1) therefore closes an unanswered call at the next non-toolResult message; a call in the last message stays open. Any code pairing calls with results must treat "never answered" as closed, or history compression stalls for the rest of the session.
