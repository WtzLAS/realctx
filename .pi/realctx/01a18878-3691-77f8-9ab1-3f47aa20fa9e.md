Pi's `branchWithSummary` appends a `branch_summary` entry as a child of the branch-from entry, and `buildSessionProjection` projects it in place, so a `branchSummary` message can appear in the middle of the messages, not only at the start (compaction summaries are only first). `pickChunk` in `src/history.ts` never puts a summary inside a chunk. When the run before a summary can't form a chunk, it continues after the summary, because otherwise history compression would stall for good. Regression test: "pickChunk: a branch summary mid-transcript" in `tests/history.test.ts`.
