Pi auto-retry (`_prepareRetry` → `_omitRecoveryAttempt` in pi-coding-agent `core/agent-session.js`) appends a `context_edit` entry (replacement null) to hide each failed attempt. `estimateProjectedContextTokens` (`core/compaction/compaction.js`) then ignores the last assistant usage if any `context_edit`/`compaction` comes after it, and re-estimates the WHOLE persisted projection with chars/4. With realctx that projection is the raw transcript (dropped outputs and compressed history count in full, because realctx only rewrites in the `context` event), so `ctx.getContextUsage()` / the footer % can go past 100% until the next successful response. The error assistant message itself is tiny (`content: [{text:""}]`, usage zero) and both Pi and realctx `estimateUsage` already skip error/aborted usage. Pi threshold compaction in that state uses the same inflated estimate; realctx cancels `reason: "threshold"` in `session_before_compact`. Reproduce: /tmp-style script that cuts a session jsonl before/after each context_edit line and calls `estimateProjectedContextTokens(sm.buildSessionProjection(), sm.getBranch())` (e.g. 85k → 129k).
