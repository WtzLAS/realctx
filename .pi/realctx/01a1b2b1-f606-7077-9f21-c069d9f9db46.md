`/realctx settings` (`extensions/realctx/settings-page.ts`) opens on a top-level `SettingsList` of categories from `SETTINGS_CATEGORIES`: General, Context, History, Memory, Path notes, Consolidation, each showing `summary(draft)`. The "Reset thresholds" action (id `reset`, `categoryOf` → "top") also sits there. `categoryOf(id)` assigns fields using prefixes and `GENERAL_IDS`; unmatched fields land in Memory, so new fields need a matching prefix or must be added there. Category lists remove the category's `prefix` from labels ("Context: " → ""), then capitalize. Typing a printable non-space character on the first page opens flat search across every field using full labels. Esc returns search/category → first page → close and save; tests typing at the top level therefore need two Escs to close.

Items are rebuilt per list (`shown` map with top/category/search groups) and refreshed from `draft` on every render, keeping lists consistent; reset no longer calls `updateValue`.

The `model-list` FieldDef kind supports `context.disabledModels`: `list(s)` returns entries; `set(s, text)` accepts comma-separated text or "(none)". Its `modelListPicker` submenu is a `FilterPicker` over `ctx.modelRegistry.getAvailable()`: first `✎ edit as text…` (InputSubmenu, for `*` patterns), then listed entries as `✓ entry`, then unlisted models. Enter toggles a model without closing; `FilterPicker.setItems(items, selected)` preserves filter text and highlighted value. Esc closes with `d.get(draft)`. SettingsList onChange ignores this kind because the picker updates `draft`/`dirty` itself. `FilterPicker` also accepts optional `hint` (footer line).

Tests in `tests/tui.test.ts`: "settings page: categories first…" and "settings page: disabled models are toggled…" (fakeCtx; override `ctx.modelRegistry.getAvailable`).
