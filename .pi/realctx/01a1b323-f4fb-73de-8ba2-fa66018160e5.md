How realctx handles memory paths that no longer exist:
- `src/paths.ts` `repoFiles`: `renames` = history renames (`git log -M -n 300`, cached per root+HEAD in `historyCache`) + working-tree renames from `worktreeRenames` (staged `R` entries from `git status --porcelain=v1 -z`, plus content match: tracked files deleted from the working tree vs. untracked files, via `ls-tree` blob ids and `hash-object --stdin-paths`; only 1:1 matches count, empty blobs are skipped). `clearRepoCache()` only clears the working-tree part.
- `classifyMissing(scope, repo, root)`: "deleted" if a `--no-renames --diff-filter=D` commit exists on HEAD, if the path is tracked at HEAD but gone from disk, or if git never saw it; "unknown" if it only appears on other refs (`git log --all`) or git failed. "unknown" paths are KEPT, so pruning on a feature branch never removes paths that exist on main.
- `path_state.suggestion` column now holds a JSON map missing→new path (`PathStateRow.renames`). Older rows that store a plain string are read as `{missing[0]: value}`.
- Engine methods: `checkPaths` (stores the missing paths and renames for every missing path); `followRenames(cwd)` (`paths.autoRename`, project memories only); `planPrune` → `{changes: {renames, dropped, kept, paths}[], skipped}`; `applyPrune(cwd, [{change, action: "apply"|"delete"}])` skips memories whose hash or paths changed since the plan; `prunePaths(cwd)` = apply everything, never deletes. A memory with no paths left becomes `["."]` (or `["~"]` for global), not deleted.
- Extension: `followMoves` in `extensions/realctx/index.ts` runs at session_start (and then warns about stale paths) and at turn_end (throttled to 30 s; subagents skip the rewrite). `/realctx prune-paths` UI is in `extensions/realctx/prune-page.ts` (showText overview: `a` apply all / `r` review with `ui.select` per change).
- Tests: tests/pathnotes.test.ts "followRenames follows staged renames and plain moves…" and "prune review: …".
