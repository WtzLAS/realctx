Fix in `~/Projects/realagy` (uncommitted as of 2026-11-07), pi provider `antigravity`, running `agy acp`:
- `WarmSession.bytes` estimates ACP-held context using `messageBytes` in `src/transcript.ts`: serialized text + 6 KB per image. Warm plans carry `hidden` = held bytes minus pi's current view of the matched prefix; `warmAfterTurn(..., hidden)` carries this into the next checkpoint so small realctx drops accumulate.
- Reclaim settings are adjustable in `/realagy settings` and `~/.pi/agent/realagy/config.json`: `reclaimContext` (default true; false disables reclaim but still tracks checkpoint `bytes`), `reclaimMinTokens` (default 8000; × `BYTES_PER_TOKEN`=4 → `minBytes`), `reclaimMinPercent` (default 10, range 0–100 → `minShare`), and `reclaimColdMinutes` (default 5 → `coldMs`; 0 disables the cold rule).
- `matchWarm` rejects a checkpoint with reason `context-reclaimed` when hidden bytes meet the policy minimum AND either the hidden share meets the policy threshold or the latest reply exceeds the enabled cold threshold. Replanning starts a fresh session, releasing reclaimed context.
- `src/settings.ts` defines `reclaimPolicy(config)`, `reclaimSettings`, and `RECLAIM_SETTING_KEYS`. Normalization omits default-valued keys, preserving existing config deepEqual expectations of `{noAutoCompaction, agentProfile}`. `extensions/index.ts` supplies live per-request policy via `createStreamSimple({ reclaim: () => reclaimPolicy(config) })`. `planTurn`/`planTurnFrom`/`measureWarm` in `src/transcript.ts` accept an optional policy: default `DEFAULT_RECLAIM_POLICY`, null = off.
- TUI rows 6–9 cycle reclaim presets; the fallback menu places the four entries before "Save and close" (index 10, Cancel 11).
- Mid-turn, `createStreamSimple` in `src/provider.ts` calls `measureWarm(context, sessions.step)` before resolving tool results; on reclaim it calls `roundTrips.failAll` + `driver.cancelActive(RECLAIM_REASON)` and plans again (fresh).
- Otherwise agy runs the tool loop natively; pi tool results resolve the MCP bridge via `deps.driver.reentry()`. Warm matching remains content-invariant for toolResult keys (`[toolName, toolCallId, isError]`) and suffix-matches leading `‹realctx-history>` summaries.
- Legacy checkpoints without `bytes` match as before: an already-bloated session only recovers after its next fresh session.
- realagy reports actual agy occupancy as `usage.totalTokens`. realctx cancels Pi threshold compaction via `session_before_compact`; realagy's default `noAutoCompaction` disables agy's checkpointer. Reclaim releases context by restarting instead.
- Historical pre-fix evidence: pipegraph2 session `2026-11-07T11-03-52` (`01a1b5ad…`) retained one ACP session across 282 assistant messages; totalTokens rose 27k→538k despite 269 realctx drops (~152k "saved") and 28 history entries.
- Alternative workaround: `context.disabledModels: ["antigravity/*"]` disables the realctx layer, allowing Pi compaction; realagy treats Pi compaction as divergence and starts fresh.
- Tests: "reclaim" tests at the end of `tests/provider.test.ts`. Run `npm ci` before `npm run check`.
