The v3 global `context.cacheTtl` was REMOVED; the universal 5m fallback is internal, not a restored global setting. Cold-cache checks use `MemoryEngine.cacheTtls` (`src/cache-ttl.ts`): `context.cacheTtlByModel` exact provider/model override first, then case-insensitive model-ID override, then automatic catalog TTL if present, then labeled native Anthropic/OpenAI 5m estimates when caching is evidenced by catalog or Pi model costs. Automatic catalog/provider resolution requires `context.cacheTtlAuto`, which defaults true. Unavailable lifetimes resolve to `300000ms` with source `placeholder`, displayed as `5m (placeholder)`; this actually triggers cold-cache drops after 5 minutes, not display-only. It applies before successful fetches, after failed fetches without cached values, for catalog models without usable TTLs/provider estimates, and when auto is false with no override. Overrides always win; previously fetched valid TTLs survive refresh failures. Pressure/emergency/flush still apply. models.dev publishes cache prices, NOT TTLs; never describe provider estimates as fetched TTLs. Background daily refresh uses an 8s timeout, in-flight dedup, failure backoff, and last-good snapshot at `realctx base/model-cache-ttls.json`. Gateways do not inherit vendor estimates. Extended retention requires a manual override. Settings picker resembles Disabled models: TTL/source in right column, Enter edits duration, overrides use exact hint `(overrided)`, empty/auto removes that key's override, and Refresh fetches catalog manually. No prompts or credentials go to the public catalog. This user-requested placeholder policy supersedes threshold-only/unknown-lifetime/Infinity statements in the v3 settings/safe-window memory; all other v3 defaults, migration, backups, safe-window and test-command facts remain unchanged.
