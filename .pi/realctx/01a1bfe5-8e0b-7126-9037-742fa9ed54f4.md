The memory tools support optional `root` resolved relative to the session cwd (also absolute / ~/). A canonical directory different from cwd is read-only, even within the same repo; remember/forget reject before acquiring the engine. Recall/list/status use `MemoryEngine.readView(..., true)`: direct `scopeContext` (not engine.scopes, which migrates stores), a disposable `RealctxDB.memorySnapshot()` metadata copy and fresh in-memory `MemoryIndex.sync`. This finds unindexed files without persistent index changes, usage bumps, config/store migrations or document embedding; cached vectors still support query embedding. Foreign recall excludes session outputs/recent paths/markSeen; foreign status excludes session context. Tests in tests/memory-roots.test.ts compare files and SQLite total_changes; exclude realctx.sqlite-shm because even SELECT-only reads update WAL reader marks there.
