Pi 1.5.1 changed `cacheWarming` to default `"idle"`: Pi re-sends the last request (as realctx transformed it) to keep the prompt cache warm for up to 30 min between runs, and also during long tool runs. Each successful refresh is persisted as a session `usage` entry `{type:"usage", kind:"cache_warm", provider, model, timestamp(ISO)}` after the assistant message it keeps warm; it never enters the model context. `lastCacheWrite(messages, ctx)` in `extensions/realctx/context-layer.ts` returns the latest such refresh for `ctx.model.provider` that comes after the last assistant message on the branch, falling back to the last assistant timestamp. `ContextLayer.transform` uses it for the cold-cache trigger, so drops don't break a cache Pi is paying to keep warm. Test: "Pi cache-warming refreshes after the last response keep the cache warm" in `tests/context.test.ts` (push usage entries into `h.entries`). Pi's `cache_warming_decision` extension event can also override warm/stop; realctx doesn't use it.
