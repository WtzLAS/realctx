Since Pi 1.5.0 the published `@earendil-works/pi-ai` no longer depends on TypeBox: `StringEnum` returns a `@earendil-works/pi-schema` `Schema<T>`, and pi-ai no longer re-exports `Type`/`Static`/`TSchema`. Only inside Pi does the loader map `@earendil-works/pi-ai` to an "extension view" whose StringEnum is TypeBox `TUnsafe`. Using pi-ai's StringEnum inside `Type.Object` from `typebox` makes param types `{}` (tsc error TS2538 on `SCOPE_ARG[params.scope]`). `extensions/realctx/tools.ts` therefore defines its own `StringEnum` = `Type.Unsafe<T[number]>({ type: "string", enum: [...values], description })` and doesn't import pi-ai there. Import `Type`/`TSchema` from `typebox`.
